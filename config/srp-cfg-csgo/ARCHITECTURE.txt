SrP-CFG v3 ownership model (CS:GO Source 1 port)

autoexec.cfg (copy config/autoexec_csgo.cfg to csgo/cfg/autoexec.cfg)
  -> srp-cfg-csgo/runtime/init.cfg
     -> public commands plus included module runtime.cfg files
  -> srp-cfg-csgo/user/custom.cfg
     -> optional srp_apply_default starting point
     -> user-owned overrides below it

Runtime
  Stable feature implementation. Each feature/mode keeps persistent alias definitions
  in its own runtime.cfg so config.cfg-synced bindings remain executable across sessions.
  Runtime files never apply personal preferences or physical keymaps.

Module
  Every feature and mode uses the same local structure:
    runtime.cfg       persistent aliases only
    settings.cfg      feature/mode state without physical bindings
    keymap.cfg        physical bindings only
    with-keymap.cfg   settings followed by keymap

Preset
  Default is included in this CS:GO port as a starting-point example exposed through
  the safe srp_apply_default alias; users may enable it near the top of custom.cfg and
  continue overriding below it.
  Valve is an auditable baseline using CS:GO engine defaults and binddefaults.

User
  srp-cfg-csgo/user/custom.cfg is the only file ordinary users are expected to edit.
  It runs after Runtime and should remain safe across runtime updates.

config.cfg (Source 1 persistence)
  CS:GO owns config.cfg persistence for archived ConVars and bindings. See CONFIG-NOTICE.txt
  for details on host_writeconfig and Steam Cloud interaction.
