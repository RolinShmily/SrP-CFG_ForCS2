# i18n

SrP-CFG 的双语文案集中在 `srp_core`，通过全局键值表提供给 CLI 与 GUI。语言状态为进程级全局变量；同一进程内所有 `tr()` 调用共享同一语言。

## 表结构

核心表位于 `src/core/src/i18n.cpp`：

```cpp
const std::unordered_map<std::string_view, std::string_view> g_dictZh = { ... };
const std::unordered_map<std::string_view, std::string_view> g_dictEn = { ... };
```

- `g_dictZh`：简体中文
- `g_dictEn`：英文
- 运行时 `g_currentLanguage` 决定读取哪张表。

当前表规模约 370+ 个键，覆盖 CLI 输出、GUI 标签、错误提示、页面标题、设置项、视频选项、地图标注等。

## 键命名约定

采用 `域.子域.标识` 三级点分结构：

| 域 | 示例 |
|---|---|
| `about.*` | 关于页面 |
| `appupdate.*` | 软件更新 |
| `preferences.*` | 设置/偏好 |
| `pkg.*` | 配置包操作 |
| `media.*` | 媒体编辑与外部冲突 |
| `video.*` | 视频设置标签与错误 |
| `annotations.*` | 地图标注 |
| `assembly.*` | 自由装配（特性/模式/Valve） |
| `detect.*` | 环境探测 |
| `nav.*` | 侧边栏导航 |
| `title.*` | 标题栏与公共操作 |
| `overview.*` | 总览页面 |
| `presets.*` | 预设包 |
| `feedback.*` | 通用反馈与账号切换 |

错误键通常以操作域为前缀，例如 `pkg.write_failed`、`video.running`、`assembly.binding_conflict`。

## CLI 使用方式

CLI 通过 `--zh` 或 `--en` / `--english` 在 `main()` 中调用：

```cpp
srp::core::setLanguage(useEnglish ? srp::core::Language::EnUS : srp::core::Language::ZhCN);
```

随后所有 `srp::core::tr(key)` 按当前语言返回对应文本。

## GUI 使用方式

GUI 中 `PreferencesController` 从 QSettings 读取 `ui/language`（`zh` 或 `en`），在构造时同步调用 `srp::core::setLanguage()`。QML 侧通过 `OverviewController.tr(key, lang)` 获取文案，或绑定到 `PreferencesController` 的信号刷新界面。

语言保存路径：`%APPDATA%/SrP/SrP-CFG.ini`（UserScope INI），包含：
- `ui/language`
- `ui/fontFamily`
- `ui/darkMode`

## 新增文案步骤

1. **在 `i18n.cpp` 的 `g_dictZh` 和 `g_dictEn` 中同步添加键值对**。两种语言必须一一对应；缺失会导致运行时返回 `""`。
2. **使用英文键名**，值按语言填写。键本身不使用中文。
3. **在 core 接口或控制器中通过 `tr("your.new_key")` 引用**。
4. **CLI 立即生效**；GUI 若需动态刷新，须确保相关 QML 绑定到语言变化信号或在初始化时读取。
5. **测试时可通过 `srpcfg <command> --en` / `--zh` 验证输出**。

## 已知限制

- **全局语言状态**：`setLanguage` 修改全局变量 `g_currentLanguage`；同一进程内无法同时输出两种语言。
- **进程级隔离**：CLI 和 GUI 是不同的进程，语言选择互不干扰；暂存区路径通过 `--store` 同步，但语言不会通过暂存区传递。
- **缺失键**：若键不存在于当前语言表，`tr()` 返回空字符串，不会回退到另一语言。
- **无运行时热加载**：文案表编译进二进制；修改后需重新构建 `srp_core`。
